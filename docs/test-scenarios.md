# CHAMPUS 할로윈 부스 테스트 시나리오

총 **65개: E2E 자동화 58개(SC-01~58), 수동 7개(SC-59~65)**. 각 자동 시나리오 ID는 `e2e/*.spec.js`의 테스트 제목에 연결된다. 여러 시나리오를 한 테스트에서 검증하거나 입력값별로 나누므로 시나리오 수와 테스트 수는 다르다.

공통 사전 조건: 별도 언급이 없으면 새 브라우저 컨텍스트, 저장값 없음, 한국어, 라이트 모드, 390×844 또는 320×844 Chromium이다. 모든 자동 테스트는 `vite --mode e2e`를 사용한다. 실제 Firebase SDK 대신 메모리 I/O를 사용하며, 외부 HTTP 요청은 차단한다. 실제 계정이나 학생 개인정보를 쓰지 않는다. 날짜는 2026-10-31 14:30 KST로 고정한다. 실행과 seam 설명은 [E2E 안내](../e2e/README.md)를 참조한다.

## 설문 정상 흐름과 데이터 계약

1. **SC-01 설문 정상 완료와 전체 진행도** — 자동, `survey.spec.js`
   - 사전 조건: S0, Firebase mock 성공.
   - 절차: 독서모임 선택 → 요일 생략 → 정기 참여 → 신앙 공동체 아니요 → 의견 생략 → 동의 → 이름·학과·학번·전화번호 입력 후 제출한다.
   - 기대 결과: S0~S10의 진행도는 `0,10,20,30,40,50,50,60,70,80,90,100`, pill은 `📝 0/9`부터 `📝 9/9`까지 표시한다. S3-1은 4/9, S4와 S5는 모두 5/9이다. 이름이 있는 핫초코 교환권이 나온다. `responses`에 한 번 저장하며 문서는 정확히 14개 키다: `schemaVersion, activities, activityOther, days, participation, seekingFaithCommunity, comment, name, department, studentId, phone, consent, createdAt, expireAt`. 버전은 숫자 1, 선택값은 문자열 배열, 신앙 여부는 boolean, 기타는 null, 나머지 입력은 문자열, consent는 true, createdAt은 서버 타임스탬프 sentinel, expireAt은 제출 시각+365일의 Timestamp이다. 전화번호는 숫자 문자열 `^01[0-9]{8,9}$`이다.

2. **SC-02 모든 활동·요일의 저장 ID와 정렬** — 자동, `survey.spec.js`
   - 사전 조건: S1, Firebase mock 성공.
   - 절차: 일반 활동 10개를 역순으로 선택하고 기타에 공백을 포함한 글을 쓴다. 일~월 역순 선택, 가끔 참여, 신앙 공동체 네, 의견·이름·학과를 공백과 함께 입력하고 제출한다.
   - 기대 결과: 활동은 `union-worship, small-group, book-club, vibe-coding, futsal, career-mentoring, edu-volunteer, champs-study, happy-bridge, perfume-workshop, other` 순이다. 요일은 `mon..sun` 순이다. `participation=occasional`, 신앙 여부=true, 기타·의견·이름·학과의 양끝 공백이 제거된다. 나머지 키와 타입도 SC-01 계약을 따른다.

## 설문 검증과 배타 선택

3. **SC-03 활동 필수·다중 선택·선택 해제** — 자동, `survey.spec.js`

4. **SC-04 고민 중 활동의 양방향 배타성** — 자동, `survey.spec.js`
   - 사전 조건: 활동 복수 선택 상태.
   - 절차: `아직 고민 중이에요` 선택 → 기타 선택 → 고민 중 선택·해제한다.
   - 기대 결과: 고민 중을 고르면 다른 모든 선택을 지운다. 다른 활동을 고르면 고민 중을 지운다. 고민 중 자체도 토글된다.

5. **SC-05 기타 입력 필수·공백·100자 한도** — 자동, `survey.spec.js`
   - 사전 조건: S1.
   - 절차: 기타를 고르고 빈 값·공백을 입력한 뒤 Enter, 101자를 입력한 뒤 Enter를 누른다.
   - 기대 결과: 기타 입력으로 포커스가 이동한다. 빈 값·공백에서는 `기타 활동을 적어 줘!`가 비활성이고 이동하지 않는다. 100자까지만 입력되며 유효하면 S2로 간다.

6. **SC-06 기타 선택 해제 후 null·고민 중 ID 저장** — 자동, `survey.spec.js`
   - 사전 조건: S1에서 기타에 글을 입력했다.

   - 기대 결과: 기타 입력은 숨겨진다. 메모리에 남은 글과 무관하게 `activities=['undecided']`, `activityOther=null`, `days=['flexible']`로 저장된다.

7. **SC-07 요일 복수 선택·토글·생략** — 자동, `survey.spec.js`
   - 사전 조건: S2, 요일 없음.
   - 절차: 월~일을 선택하고 선택들을 해제한 뒤 건너뛰기를 누른다.
   - 기대 결과: 선택 중에는 CTA가 `다음`, 비어 있으면 `건너뛰기`다. 생략해도 S3로 이동하고 빈 days가 허용된다.

8. **SC-08 일정 유동의 양방향 배타성** — 자동, `survey.spec.js`

   - 기대 결과: 일정 유동을 고르면 월~일이 모두 해제된다. 요일을 고르면 일정 유동이 해제된다. 자체 토글도 된다.

9. **SC-09 참여 방식 필수·단일 선택·저장값** — 자동, `survey.spec.js`
   - 사전 조건: S3, 무선택.

   - 기대 결과: 무선택에서는 `하나 골라 줘!`가 비활성이다. 한 번에 하나만 aria-checked=true이고 저장값은 각각 `regular / occasional / info-only`다.

10. **SC-10 신앙 공동체 필수·네/아니요** — 자동, `survey.spec.js`

11. **SC-11 의견 선택 입력·공백·1000자 한도** — 자동, `survey.spec.js`

13. **SC-13 이름 1~30자와 공백** — 자동, `survey.spec.js`

16. **SC-16 전화번호 검증과 입력 제한** — 자동, `survey.spec.js`
    - 사전 조건: S9.

17. **SC-17 전화번호 표시와 저장 정규화** — 자동, `survey.spec.js`의 3개 매개변수 테스트.

    - 절차: `01012345678`, `0111234567`, `+82 10-1234-5678`을 각각 입력하고 Enter 제출한다.

18. **SC-18 Enter와 한글 조합 보호** — 자동, `survey.spec.js`

## 활동 소개 시트와 뒤로 가기

19. **SC-19 일반 활동 10개 소개** — 자동, `sheet.spec.js`
    - 사전 조건: S1.
    - 절차: 각 활동의 소개 보기 버튼을 열고 닫는다.
    - 기대 결과: 각기 올바른 제목·설명·일정을 보여 주며 dialog 이름과 aria-modal이 있다. 기타와 고민 중에는 소개 버튼이 없다. 폭을 벗어나지 않는다.

20. **SC-20 시트 선택·선택 취소·닫기** — 자동, `sheet.spec.js`
    - 사전 조건: 고민 중 선택 상태.
    - 절차: 독서모임 시트 → 이 활동 고르기 → 다시 열어 닫기 → 다시 열어 선택 취소하기.
    - 기대 결과: 고르면 해당 활동이 선택되고 고민 중은 해제된다. 이미 선택했으면 안내와 `선택 취소하기`가 보인다. 닫기는 선택을 유지하고 취소는 선택을 지운다.

21. **SC-21 시트 닫기와 포커스 복원** — 자동, `sheet.spec.js`
    - 사전 조건: 소개 시트 열림.
    - 절차: Escape, 바깥 배경, 브라우저 뒤로 가기로 각각 닫는다.
    - 기대 결과: 시트만 닫히고 S1과 선택을 유지한다. 배경 app의 inert가 해제되고 소개 보기 버튼으로 포커스가 돌아온다.

22. **SC-22 이전 버튼·브라우저 뒤로 가기 답변 유지** — 자동, `survey.spec.js`
    - 사전 조건: S9까지 모든 필수 입력 완료.
    - 절차: 이름·학과·학번을 거슬러 확인하고 의견·요일을 수정한다. 브라우저 뒤로 가기로 S1, 이전 버튼으로 S0에 갔다가 S9까지 다시 진행한다.
    - 기대 결과: 활동, 요일, 참여 방식, 신앙 여부, 의견, 이름, 학과, 학번, 전화번호를 보존한다. S0에서는 이전 버튼이 비활성이다.

## 제출과 저장 범위

23. **SC-23 전송 중 이중 탭·Enter 방지** — 자동, `submission.spec.js`
    - 사전 조건: S9, 유효한 전화번호, pending mock.
    - 절차: 제출을 연속 두 번 누르고 Enter를 반복한다. 브라우저 뒤로 가기도 시도하고 pending을 해제한다.
    - 기대 결과: `보내는 중…`과 이전 버튼이 비활성이다. S9를 유지하고 SDK 호출과 성공 쓰기는 각각 한 번이다. 해제 후 S10으로 간다.

24. **SC-24 전송 실패·재시도 성공** — 자동, `submission.spec.js`
    - 사전 조건: failure mock.
    - 절차: 제출 → 실패 확인 → success+delay mock으로 변경 → 다시 보내기.
    - 기대 결과: 붉은 `전송이 안 됐어요` 배너와 `다시 보내기`가 표시되고 버튼에 포커스가 간다. 실패 때 완료 저장값은 없다. 같은 답변으로 다시 전송하며, 전송 중 CTA 비활성, 성공 후 S10과 배너 숨김이다. 시도 2회, 성공 1회다.

25. **SC-25 응답 없는 전송 타임아웃** — 자동, `submission.spec.js`
    - 사전 조건: pending mock.
    - 절차: 제출하고 Playwright 가상 시계를 15,001ms 진행한다.
    - 기대 결과: 무한 로딩 대신 실패 배너·활성 재시도 버튼이 나온다. 실제 15초 대기나 고정 sleep은 사용하지 않는다.

26. **SC-26 완료 뒤 새로고침** — 자동, `submission.spec.js`

    - 기대 결과: 이름이 있는 S10 교환권과 수업 CTA를 바로 표시한다. 설문이나 제출 요청을 재실행하지 않는다.

27. **SC-27 진행 중 새로고침** — 자동, `submission.spec.js`

    - 기대 결과: 공급자 리디렉션과 허용 목록이 맞고 다른 사용자에게 응답을 노출하지 않는다. 자동 테스트는 공급자 UI를 검증하지 않는다.

60. **SC-60 실제 Firestore 권한·타임스탬프·보관** — 수동, E2E 자동화 안 함.
    - 사전 조건: 승인된 스테이징 또는 별도 Rules emulator, 테스트 데이터만 사용.
    - 절차: 비관리자 읽기/삭제 거절, 관리자 허용, 잘못된 문서 거절, 서버 createdAt·365일 expireAt, 만료 정리 배치 권한을 확인한다.
    - 기대 결과: Rules가 실제 계약과 접근 권한을 강제하고 승인된 만료 건만 삭제된다. 본 suite는 SDK I/O mock이므로 서버 권한과 서버 시각을 증명하지 않는다.

61. **SC-61 스크린리더와 실제 키보드** — 수동, E2E 자동화 안 함.
    - 사전 조건: VoiceOver/Safari 또는 TalkBack/Chrome 및 외장 키보드.
    - 절차: 설문·시트·퀴즈·오류·쿠폰·관리자 표를 읽고 키보드로 조작한다.
    - 기대 결과: 질문·선택 상태·오류·진행도·피드백이 이해 가능한 순서로 읽힌다. 포커스가 보이고 이름 없는 컨트롤이나 막힌 조작이 없다. 자동 검사만으로 전체 접근성 적합성을 주장하지 않는다.

62. **SC-62 실제 휴대폰 키보드·안전 영역·확대** — 수동, E2E 자동화 안 함.
